# Pirsch Analytics

> Pirsch is a privacy-first, cookie-free web analytics platform built and hosted in Germany by Emvi Software GmbH. It tracks page views, sessions, custom events, conversion goals, funnels and traffic sources without storing personal data, and exposes everything through a REST API at https://api.pirsch.io/api/v1 with OAuth2 client-credentials tokens or write-only `pa_` access keys.

## Authentication

- Base URL: `https://api.pirsch.io/api/v1`
- OAuth2 client credentials: `POST /token` with `client_id` and `client_secret`, returns `access_token` + `expires_at`; send as `Authorization: Bearer <token>`
- Access keys: `pa_`-prefixed static keys, sent the same way, **write-only** (tracking endpoints only)
- A 401 means the token expired — request a new one and retry
- Detail: authentication/pirsch-authentication.yml

## Rate limits

- Security endpoints (login, password reset): 10 requests/minute
- Configuration endpoints (`/domain`, `/member`, `/client`, `/goal`, `/funnel`, `/webhook`, `/filter`, `/link`, `/report`, `/view`): 60 requests/minute
- Statistics and data-collection endpoints: currently unlimited
- Signalled by `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset` and `Retry-After`
- Detail: rate-limits/pirsch-rate-limits.yml

## What Pirsch does NOT publish

Recorded so an agent does not go looking. All probed 2026-08-13:

- No OpenAPI/Swagger document (`/openapi.json`, `/openapi.yaml`, `/swagger.json` on api.pirsch.io all 404)
- No GraphQL endpoint
- No first-party MCP server (`mcp.pirsch.io` is a wildcard SPA catch-all, not an endpoint)
- No A2A agent card at either well-known path
- No `/.well-known/` surface at all — no security.txt, no OIDC or OAuth metadata, no api-catalog
- No public status page
- No published deprecation policy or Sunset/Deprecation header support
- No idempotency-key support
- No OAuth scopes (tokens are all-or-nothing per client)
- No CLI
- No sandbox or test-mode credentials
